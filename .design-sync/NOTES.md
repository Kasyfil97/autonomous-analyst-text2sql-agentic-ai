# design-sync NOTES — BRISA (frontend/)

This is a **Next.js application**, not a component-library package. There is no
`dist/` and no shipped `.d.ts`. The sync treats `frontend/` as the package and
bundles the shared components in `frontend/components/` via an authored barrel.

## Setup this run created (all dot-prefixed, ignored by the Next.js build)

- `frontend/.ds-entry.tsx` — barrel re-exporting Sidebar, SqlBlock, TableCard,
  AppStateProvider. Passed as `--entry` so PKG_DIR resolves to `frontend/`
  (its package.json has a name) and node_modules/react resolves.
- `frontend/.ds-shims/next-link.tsx`, `next-navigation.ts` — standalone shims
  for `next/link` and `next/navigation`. Wired via `cfg.tsconfig`
  (`frontend/.ds-tsconfig.json` `paths`). Without these the real Next.js would
  be pulled into the browser IIFE and the router hooks would render blank.
  usePathname() returns `/search` → Sidebar shows a representative active nav.
- `frontend/.ds-styles.css` — Tailwind v4 `globals.css` compiled standalone via
  `frontend/.ds-compile-css.mjs` (uses `@tailwindcss/postcss`). Regenerate with
  `node .ds-compile-css.mjs` from `frontend/`. This is `cfg.cssEntry`.
- `frontend/.ds-fonts/` + `frontend/.ds-fonts.css` — self-hosted IBM Plex Sans
  (400/500/600/700) + Mono (400/500/600), latin + latin-ext subsets, downloaded
  from Google Fonts by `frontend/.ds-fetch-fonts.mjs` (reads `.ds-fonts-src.css`).
  `.ds-compile-css.mjs` appends `.ds-fonts.css` (the @font-face rules + the
  `--font-plex-sans`/`--font-plex-mono` var definitions that next/font injects at
  runtime in the real app).

## Build

```
node .ds-sync/package-build.mjs --config .design-sync/config.json \
  --node-modules ./frontend/node_modules --out ./ds-bundle
```
`--entry` comes from cfg.entry. Do NOT run `next build` — the standalone CSS +
shims replace the app runtime.

## Re-sync risks

- The compiled CSS and self-hosted fonts are regenerated by scripts, not by the
  app build. If `globals.css` tokens/utilities change, re-run `.ds-compile-css.mjs`
  before the converter.
- If a component gains a new Next.js import (e.g. `next/image`, `next/font`), add
  a shim under `.ds-shims/` and a `paths` entry in `.ds-tsconfig.json`.
- Fonts were sourced from Google Fonts (IBM Plex is OFL). Only latin/latin-ext
  subsets are shipped — non-latin content would fall back.
- The frontend dot-files (`.ds-entry.tsx`, `.ds-shims/`, `.ds-tsconfig.json`,
  `.ds-compile-css.mjs`, `.ds-fetch-fonts.mjs`, `.ds-fonts-src.css`) are the
  sync inputs. `.ds-styles.css`, `.ds-fonts.css`, and `.ds-fonts/*.woff2` are
  generated by the two scripts — regenerate them (`node .ds-compile-css.mjs`,
  and `node .ds-fetch-fonts.mjs` if you need fonts again) rather than trusting a
  stale copy. On a fresh clone, re-run the dep install in `.ds-sync/`.
- Re-sync uses the driver: `node .ds-sync/resync.mjs --config .design-sync/config.json
  --node-modules ./frontend/node_modules --out ./ds-bundle --remote <saved anchor>`
  after re-running `.ds-compile-css.mjs`. Fetch the project's `_ds_sync.json` into
  `.design-sync/.cache/remote-sync.json` first.
